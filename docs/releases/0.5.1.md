# KQuickShare 0.5.1

A bug-fix release. Existing settings and trusted devices keep working.

## Fixes

- **Large batches of files.** Receiving opened a temporary file for every
  attachment as soon as the transfer was accepted, and sending opened every
  selected file up front. With the usual limit of 1024 open files per process,
  a batch of several hundred photos failed with "Could not create file" or never
  started. Files are now opened one at a time, when their data arrives or is sent.
- **Failed first attempts from some phones.** Some phones send an informational
  frame (certificate info or progress) between the key exchange and the list of
  files. KQuickShare stopped with "Expected INTRODUCTION", and the phone had to
  retry. These frames are now skipped, and an unexpected frame type is logged.
- **Long file names.** Linux allows at most 255 bytes per file name, and a
  Cyrillic character takes two bytes. A file whose name had more than about 127
  Russian characters was received completely and then not saved. Such names are
  now shortened, keeping the extension.
- **`kquickshare --clipboard` on Wayland** sent nothing ("The clipboard is
  empty"). A command-line client has no focused window, so Qt could not read the
  Wayland clipboard. It now uses the same clipboard access as the tray button.
- **The wrong network on machines with Docker or virtual machines.** mDNS used
  the first private IPv4 address it found, which could be a container or VM
  bridge that the phone cannot reach. The interface with the default route is
  now preferred.
- If the download folder is not writable, the phone is told that the transfer
  was declined instead of the transfer failing after acceptance.
- The "Sent" notification no longer disappears when the send window is closed
  immediately after the transfer.
- While the computer is offline, the journal gets one "waiting for a network"
  message instead of one every five seconds.

## Tests and documentation

- New encrypted-transfer tests: 1000 files in each direction under a 256-file
  descriptor limit, long Cyrillic names with a name collision, and informational
  frames before the file list.
- The README no longer says that photos never change the clipboard (this has
  been an option since 0.5.0).

## Choose the right download

- `kquickshare-0.5.1.tar.gz`: source archive; extract and run `./install.sh` as your
  desktop user. Dependencies may require sudo. Requires Qt 6.8+, KF6 and OpenSSL 3.
- `kquickshare_0.5.1_amd64.deb`: **Debian 13 x86_64**, install with
  `sudo apt install ./kquickshare_0.5.1_amd64.deb`.
- `kquickshare-0.5.1-1.x86_64.rpm`: **Fedora 43 x86_64**, install with
  `sudo dnf install ./kquickshare-0.5.1-1.x86_64.rpm`.
- `kquickshare-0.5.1-alt1.x86_64.rpm`: **ALT Linux p11 x86_64** (Workstation K 11),
  install with `su -` then `apt-get install ./kquickshare-0.5.1-alt1.x86_64.rpm`.
  `kquickshare-0.5.1-alt1.src.rpm` is the matching source package.
- `PKGBUILD`: **Arch Linux**, review and run `makepkg -si` in its directory.
- `SHA256SUMS`: checksums for the attached files.

Do not install the Debian package on an arbitrary Ubuntu release, or the Fedora
RPM on openSUSE or ALT. Use the source installer if no matching package is available.

Both devices must be on the same LAN. Discovery needs UDP 5353, and incoming
transfers use TCP 53318 by default. Trust matching is based on device name, type
and IP, not a permanent verified key. This remains an AI-assisted community project.
