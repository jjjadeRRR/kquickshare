# Архитектура KQuickShare

Нативное приложение на C++20 / Qt 6 и KDE Frameworks 6. Ядро транспорта использует
Qt Network и OpenSSL 3, интерфейс — Qt Widgets, KStatusNotifierItem, KNotification
и Prison для QR-кода. WebView и отдельный серверный процесс не требуются.

## Компоненты

- `src/core/protobuf.*`: ограниченный кодек protobuf wire format для протокола.
- `src/core/crypto.*`: P-256, ECDH, HKDF, AES-CBC, HMAC, подписи QR и AES-GCM.
- `src/core/frames.*`: разбор и создание кадров Nearby / UKEY2 / Sharing.
- `src/core/mdnsresponder.*`: входящий mDNS-анонс в LAN, без avahi-daemon.
- `src/core/devicediscovery.*`: обнаружение телефонов, включая QR-объявления.
- `src/core/inboundconnection.*`: конечный автомат одного входящего соединения.
- `src/core/outboundconnection.*`: исходящая передача файлов или текста.
- `src/core/nearbyserver.*`: TCP-сервер и управление входящими соединениями.
- `src/app/receiver.*`: окно, настройки, доверие, уведомления и трей.
- `src/app/senddialog.*`: QR-код, выбор телефона и состояние отправки.
- `src/app/main.cpp`: единственный экземпляр, session D-Bus и завершение процесса.
- `src/cli/`: отладочные инструменты.
- `integration/`: необязательный QML overlay для буфера Plasma 6.8.
- `packaging/`: desktop/service-файлы и рецепт Arch Linux.

## Приём

`QTcpServer` создаёт `InboundConnection` для каждого подключения. После
CONNECTION_REQUEST, UKEY2 и CONNECTION_RESPONSE начинается шифрованный обмен
PAIRED_KEY_ENCRYPTION / PAIRED_KEY_RESULT. INTRODUCTION сообщает метаданные,
GUI предлагает принять передачу. FILE-чанки записываются во временные `.part`.
После LAST_CHUNK проверяются размер, запись и публикация полного файла без
перезаписи существующего. Сигнал завершения испускается после закрытия сокета,
чтобы вызывающий код не уничтожил его до отправки последних служебных кадров.

Уже буферизованные при принятии сокета данные обрабатываются отложенно: владелец
успевает подключить сигналы. Восстановление сервера при смене сети учитывает
соединения до INTRODUCTION, а не только видимые в GUI передачи.

## Отправка

`SendDialog` запускает обнаружение только пока оно нужно. QR-код содержит
временный открытый ключ; соответствующий закрытый ключ подписывает согласованную
аутентификационную строку. `OutboundConnection` выполняет протокол клиента,
передаёт файлы порциями с ограничением очереди записи и продолжает читать ответы
после отправки всех данных: 100% локальной записи не означает завершение обработки
на Android. Поздняя отмена остаётся ошибкой. Сбой можно повторить вручную.

## Фоновая служба и интеграции

`org.kde.kquickshare.service` — пользовательская systemd-служба Type=dbus.
Другие запуски вызывают основной процесс через session D-Bus. Автозапуск использует
XDG desktop entry. SIGTERM/SIGINT передаются в Qt event loop через self-pipe для
штатной очистки незавершённых файлов.

Dolphin передаёт пути аргументами запуска. Кнопка буфера передаёт выбранный текст
напрямую по D-Bus. Текст не интерполируется в shell-команду. Overlay буфера не
включается автоматически при установке пакета и не меняет системные файлы KDE.

## Ограничения

Транспорт — только LAN (mDNS и TCP), без BLE, Wi-Fi Direct и серверов Google.
Постоянное криптографическое спаривание не реализовано. GUI-список доверия сверяет
имя, тип и IPv4-адрес; это удобство для доверенной LAN, а не защита от другого
участника этой сети, способного подделать такие значения.

Ядро работает событийно в потоке Qt. Файловый ввод-вывод синхронный; длительные
операции диска могут задерживать интерфейс. Входящие подключения ограничены,
ожидания имеют таймауты. Независимые Python-партнёры и Qt-тесты проверяют протокол,
завершение, доверие и интеграцию, но не заменяют тестирование с реальными телефонами.
